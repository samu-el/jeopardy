# First-run / Landing UX audit

Tested against the live app (localhost:3000 plus the rooms worker on 8787) with Playwright Chromium at 1440x900 and 390x844 touch. Scripts and screenshots are in `scratchpad/ux/landing/` (s1–s5.mjs, \*.png).

## P1

- **[P1] Host reload loses the room, and the URL never shows the room code** — Where: `game-store.ts` startGame (~l.505–520) and `AppShell.tsx:18-40`; screen desk-14-host-reload.png. What's wrong: after New Game the URL stays `http://localhost:3000/`. There is no `?room=CODE`. Reloading as host drops you on Landing with `online` empty. The room and its joined players are orphaned, and the host has no code to get back in. A joiner who reloads comes back to the join card, so joiners can recover and hosts cannot. Repro: New Game, let a second browser join, reload the host tab. Suggested fix: `replaceState` `?room=CODE` once the room connects, and on load reconnect the host into that room with the persisted seat id. Also clear the param on Leave.

- **[P1] "Change game" during a game silently does nothing, and the header then shows the wrong episode** — Where: `GamePicker.tsx:83,114`, `use-archive.ts:63-81`, `game-store.ts:275-293` (setLoadedEpisode keeps the runtime when online), `RoomToolbar.tsx:132-136`; screen desk-19-afterpick.png. What's wrong: when the host picks an episode mid-game, the dialog closes and the board keeps the old clues (THE 1890s…). The RoomBar still switches to `#1 · 1984-09-10`. The new board only appears after pressing Restart, which drops everyone to the lobby, and then Begin. Nothing tells the host this. Repro: New Game, shuffle icon, By number "1", Find. Suggested fix: when in game, either confirm and deal the new board right away ("Replace the board for everyone?"), or label the pick as "Next game: #1" and keep the header on the episode actually being played.

- **[P1] Non-host players can open "Change game", and it silently has no effect** — Where: `RoomToolbar.tsx:184` (no `isRoomHost` check), `GamePicker.tsx`; screens phone-12-joiner-picker.png and phone-13-joiner-aftershuffle.png. What's wrong: a joiner sees the shuffle key and the full "New game · 9,421 episodes" picker. Pressing Shuffle closes the dialog and changes their local `loadedEpisode` (7436) while the room board stays 4019. The Onboarding card also tells joiners "The shuffle icon deals another." Repro: join a room through `?room=CODE` on a phone, tap the shuffle key, then Shuffle. Suggested fix: hide or disable the key for non-hosts (tooltip "Only the host can change the game"), and give joiners their own Onboarding copy.

- **[P1] Search is labelled "Search categories and episodes" but never searches categories** — Where: `archive-source.ts:146-149` (the text searched is only epNum, info and airDate), `GamePicker.tsx:126`; screen desk-17-search.png. What's wrong: "potent potables" and "science" both return "0 matching / Nothing matched." The same happens straight from `/api/episodes?q=science`. Repro: Change game, Browse, type "science". Suggested fix: add category names (`clue.cat`) to the searched text, precomputed per episode, or change the label to "Search by number, date or event".

- **[P1] Browse shows at most 60 of 9,421 episodes, with no paging** — Where: `GamePicker.tsx:62` (`limit: 60`), and the API supports `offset`; screen desk-16-browse.png. What's wrong: the caption says "9,421 matching" but the list stops at 60 rows. There is no "Load more", no paging and no sort control, so older episodes can only be reached by number. Repro: open Browse and scroll to the bottom. Suggested fix: load more on scroll or with a "Show more" button using `offset`, and say "Showing 60 of 9,421".

- **[P1] Invalid shared game link (`?game=`) fails silently** — Where: `AppShell.tsx:22-27`, where the `loadPublishedGame` result is thrown away; screen desk-21-badgame.png. What's wrong: `/?game=doesnotexist` shows the plain Landing with no message. The error string "That game link is not valid any more." is never shown, and the bad param stays in the URL. Repro: open `/?game=doesnotexist`. Suggested fix: send the `{ok:false,error}` to a Landing banner (for example `dealError` in the store) and remove the `game` param.

- **[P1] A TV display link to a closed room shows "Connecting…" forever, plus a QR code for the dead room** — Where: `AppShell.tsx:30-34`, `game-store.ts:403-411` (a `false` return from joinAsDisplay is ignored, and `displayMode` stays true); screen desk-22-baddisplay.png. What's wrong: `/?room=QQQQ&display=1` shows an empty board with "CONNECTING…" and a "PLAY ALONG QQQQ" QR code with no end. A TV has no keyboard, so it cannot recover. Repro: open that URL. Suggested fix: when the lookup fails, show "Room QQQQ isn't open. Waiting for the host…", retry, and offer an exit.

- **[P1] The home wordmark leaves the socket connected, and the next "New Game" reuses the old room** — Where: `RoomToolbar.tsx:107` (`setScreen("landing")` without `leaveOnlineRoom`), unlike the Leave key at 207-211. What's wrong: after clicking the wordmark, Landing shows while `online.status === "connected"`. New Game then re-deals into the same room (X5TN, same code, same players) and swaps the board for anyone still in it. Pressing Join on another code from there calls `runtime.destroy()` without `leave-game`, which leaves a ghost seat. Repro: New Game, click the wordmark, New Game again, and compare `online.roomId`. Suggested fix: make the wordmark behave like Leave, with a confirm while a game is running, or show "Return to room CODE" on Landing while still connected.

- **[P1] New Game seats you as "Player XXX", with no bots and no prompt for a name** — Where: `Landing.tsx:37-47` (a name field only appears on the join card), `game-store.ts:169` (`initialBots = []`); screen desk-04-board.png. What's wrong: the host's podium reads "PLAYER EAC" and the room is "1 IN ROOM". The Landing promises "Bots that play", but a new game has no bots and adding them is buried in More > Players. A first-run user gets a lone board with a random name. Repro: open a fresh profile and click New Game. Suggested fix: an optional name field beside New Game, reusing the join card's field, and either one default bot or a clear "Add a bot" button on the empty podium row.

## P2

- **[P2] Onboarding modal: Escape does nothing, focus is not moved into it, and it has no accessible name** — Where: `Onboarding.tsx:36-53`. What's wrong: axe reports `aria-dialog-name` (serious). Escape leaves the dialog open, and Tab lands on the page behind it (focus is not trapped). Repro: New Game in a fresh profile, press Esc, then Tab. Suggested fix: use MUI `Dialog` with `aria-labelledby`, or add an Esc handler, `autoFocus` on "Let's play" and a focus trap.

- **[P2] Onboarding copy doesn't fit phones or joiners** — Where: `Onboarding.tsx:70-84`; screen phone-09-joined.png. What's wrong: it says "Press Space the moment the lights come on" on a touch phone that has no Space key. Joiners are told "Your board is dealt… The shuffle icon deals another," which they cannot do. Suggested fix: switch the copy on `pointer: coarse` ("Tap the buzzer") and on host vs joiner.

- **[P2] Join card: Enter in the name field doesn't submit, focus isn't moved there, and Esc doesn't cancel** — Where: `Landing.tsx:120-172`. What's wrong: after Enter on a room code, focus sits on BODY. Enter inside "Your name" does nothing. The card is `role="dialog"` but behaves like neither a dialog nor a form. Repro: type ZZZZ, press Enter, then press Enter again. Suggested fix: wrap it in a `<form onSubmit>`, `autoFocus` and select the name field, and add Esc to Cancel.

- **[P2] A join error stays on Landing after Cancel** — Where: `Landing.tsx:157-167,235-239` (Cancel doesn't clear `joinError`). What's wrong: after a failed join, pressing Cancel still shows "That room is not open…" under the main buttons. Repro: join ZZZZ, press Join, then Cancel. Suggested fix: `setJoinError(null)` in Cancel.

- **[P2] Room code box: max length 6 breaks pasted invite links, and the minimum is 3 when codes are 4** — Where: `Landing.tsx:213,229`, `room-code.ts:10`. What's wrong: pasting `http://…/?room=U6P6` is cut to "HTTP:/". The field accepts "ABC-12" and 3-character codes that never exist. Suggested fix: on paste, pull `room=` out of a URL, strip anything not in the code alphabet, and enable Join at exactly 4 characters.

- **[P2] Picker errors are raw HTTP text, and filters can combine into empty sets** — Where: `archive-client.ts:34,57`, `GamePicker.tsx:73-81`. What's wrong: Kids + 80s then Shuffle shows "Failed to load episodes (404)". A bad number shows "Failed to load episode 999999 (404)". Decade chips aren't narrowed by the chosen theme. The friendly fallback in `startRandomGame` ("Could not reach the episode archive…") never appears, because `error.message` is always set. Suggested fix: map 404 to "No Kids episodes from the 80s. Try another era" or "No episode #999999", map 5xx to the archive-unavailable text, and filter decades by theme.

- **[P2] Browse shows "0 matching / Nothing matched." while it loads, and hides load failures** — Where: `GamePicker.tsx:59-71,131-147`, `use-archive.ts:25` (no `.catch`). What's wrong: on opening Browse the caption reads "0 matching / Nothing matched." until the fetch returns, because `busy` is never set for list fetches. A 502 from `fetchEpisodeList` becomes an unhandled rejection and still shows "Nothing matched." Suggested fix: add a separate `listLoading` state and a caught error state with Retry.

- **[P2] Picker tabs are cut off on phone** — Where: `GamePicker.tsx:96`; screen phone-12-joiner-picker.png. What's wrong: at 390px the third tab reads "BY NUM", clipped with no scroll hint. Suggested fix: `variant="fullWidth"` or `scrollable` with `allowScrollButtonsMobile`, or a shorter label ("Number").

- **[P2] Results "Again" and "Lobby" do the same thing, and there is no "new episode" path** — Where: `Room.tsx:62` (both call `exitToLobby`), `ResultsView.tsx:81-96`. What's wrong: "Lobby" with a home icon doesn't go home or leave. Both reload the same episode. Suggested fix: make "Lobby" (or a new "New game") open the picker or deal a random episode, and give Home/Leave its own action.

- **[P2] Restart has no confirmation and actually means "back to lobby"** — Where: `RoomToolbar.tsx:199-203`, `game-store.ts:526-540`. What's wrong: one click mid-game wipes every score in a shared room and drops the room to a pre-Begin lobby (desk-20-after-restart.png), even though the tooltip says "Restart". Suggested fix: confirm when scores are non-zero, and rename to "Reset to lobby" or re-deal and start right away.

- **[P2] Landing has no `<h1>` and no `<main>` landmark** — Where: `Landing.tsx:93-118`, `Wordmark`. What's wrong: axe reports `page-has-heading-one`, `landmark-one-main`, and `region` ×5. Suggested fix: render the Wordmark as an h1 with a visually hidden "Jeopardy!", and use `component="main"` on the centre Box.
