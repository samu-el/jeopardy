# Accessibility audit — Jeopardy rebuild

Method: axe-core 4.x (wcag2a/aa, 21a/aa, 22aa, best-practice) injected via Playwright/Chromium into every state; keyboard-only walk-throughs; DOM probes for focus/live regions; viewport reflow (320px, 640px = 200% of 1280), OS `prefers-reduced-motion: reduce`, root-font 200%, WCAG 1.4.12 text-spacing. Scripts + screenshots: `scratchpad/ux/a11y/` (`flow1..5.mjs`, `*.png`, `flow*.json`). States covered: landing, onboarding, board, clue (reading/buzz-open/answering/judging/after-judge), Daily Double wager+answer, Final Jeopardy wager/answer/judge, results, shortcuts, settings, More menu, game picker, transcript, replay, players, builder, chat, subtitles, join card + failed join, display mode (board + clue).

Axe totals: no critical/serious hits on the board grid itself (gold-on-blue tiles pass). Serious hits concentrated in dialogs, judge bench, results, picker, chat. Every screen also flags `landmark-one-main`, `page-has-heading-one`, `region` (see P2 item).

---

## P0

**[P0] Screen-reader users get no announcement of the game: clue text, buzz, verdict, score, timer**

- Where: `src/components/ClueStage.tsx` (clue text), `Podium.tsx` (score, buzz light `aria-hidden`), `BuzzLights.tsx` (readout `aria-live="off"`), `GameSurface.tsx:169` (clue overlay `role="dialog"` with no focus/aria-modal).
- What: The only live region during play is the seconds readout, explicitly `aria-live="off"`. Opening a clue does not move focus into the clue and the clue text is not in any live region (probe: `clue text inside live region? false`, `containsFocus=false`). Who rang in ("Sam rang in" label), correct/incorrect, and score changes (`$0 → -$200`) produce no announcement; after judging the live-region list was `[]`. The only way the clue is spoken is the optional TTS voice (sound off by default) or the Subtitles bubble, which is off by default and a conditionally-mounted `role=status` (unreliable on first insert). Product brief promises "screen-reader-friendly state".
- WCAG: 4.1.3 Status Messages (AA), 1.3.1, 2.4.3.
- Repro: New Game → Tab to `Math, $200` → Enter. With NVDA/VO nothing is read; `document.activeElement` is `<body>`. Buzz, answer "seven": AI judge marks it wrong, score turns red, nothing announced.
- Fix: One persistent, always-mounted polite live region (e.g. `GameAnnouncer` in Room) fed by typed game events: "Math for $200: <clue text>", "Buzzers open", "You rang in — 10 seconds to answer", "Sam rang in", "Correct/Incorrect, Sam now $400", "5 seconds left" (at thresholds only). Move focus into the clue region (`tabIndex=-1`, heading with clue category/value) on open.

## P1

**[P1] Focus is dropped to `<body>` at every phase change**

- Where: Board tile → clue open; answer submit; clue close/auto-advance; results screen; join card; failed join. `PodiumClueButtons.tsx:29-33` autofocus relies on `clue.canBuzz`, which is a snapshot value and is never true on the client when readout ends, so the buzzer never receives focus.
- What: Probes: `focus after opening clue: body`, `focus once buzzer enabled: body`, `focus after answer submitted: body`, `focus back on board: body`, `focus at results: body`, `join focus: body`, `focus after failed join: body`. Keyboard users restart Tab order from the top toolbar each clue (10 stops before the board).
- WCAG: 2.4.3 Focus Order, 3.2.1/3.2.2 (context change without focus handling).
- Fix: Explicit focus plan: clue open → clue heading/region; buzz open → buzzer (derive from `useClueTurn().canIBuzz`, not `clue.canBuzz`); after submit → "Answer locked in" status; clue close → the tile just played (or next pickable tile); results → winner heading; join card → name field; join error → the error (`role="alert"`).

**[P1] Space bar is hijacked globally during a clue — focused buttons can't be activated with Space**

- Where: `ClueControls.tsx:58-63` (window keydown; only INPUT/TEXTAREA exempted).
- What: With a clue up, focus the toolbar "Settings" button and press Space: a buzz is sent and the popover does not open (probe: `{"buzzed":1,"popoverOpen":false}`). Same for Reveal/Next clue/Home/Leave room/menu items, and any button inside an open dialog (Shortcuts, Picker, More menu) — Space buzzes instead.
- WCAG: 2.1.1 Keyboard; 2.1.4 Character Key Shortcuts (related).
- Fix: Only handle Space when `event.target` is body/board/clue region or the buzzer itself; ignore when target is any `button, [role=button], [role=menuitem], select, [contenteditable]` or inside `[role=dialog]`/popover.

**[P1] First-run Onboarding modal is not keyboard-accessible (no focus, no trap, no Esc, no name)**

- Where: `Onboarding.tsx` (hand-rolled `role="dialog" aria-modal="true"`).
- What: Focus stays on body when it opens; Tab goes to the toolbar _behind_ the overlay (Home, room code, Change game…) where focus is invisible under the 78% scrim; the "Let's play" button is last in DOM so it's reached only after every board control; Escape does nothing (`onboarding after Escape visible true`); axe `aria-dialog-name` (serious).
- WCAG: 2.4.3, 2.1.2, 4.1.2, 2.4.11 Focus Not Obscured (AA, 2.2).
- Fix: Use MUI `Dialog` (focus trap, Esc, restore), `aria-labelledby` the "Three steps…" heading, autofocus "Let's play".

**[P1] Timers can't be extended/turned off; typed answer is discarded on timeout; answer auto-hides after ~3.5s**

- Where: `src/lib/realtime/room-host.ts:37-43` (answer 10s, wager 20s, final 30s, autoAdvance 3.5s, roundIntro 2.6s); only Buzz window is user-adjustable (5–20s, verified it does reach the room: measured 20000ms).
- What: Typed "partial answ" without Enter → window closed at ~9.75s and the room recorded `""` — the partially typed answer is lost. Daily Double / Final wagers and answers have fixed limits with no "more time" or host pause. The correct response and verdict stay on screen ~4.4s then the board returns, with no way to hold it (autoAdvance not in Settings). The buzz _race_ can claim the real-time exception, but the answer/wager windows (especially solo, DD and Final, where nobody is racing) cannot.
- WCAG: 2.2.1 Timing Adjustable (A), 2.2.2 (auto-updating content).
- Fix: Host/room setting "Extended time" (×2/×3/off) for answer, wager, final and auto-advance; submit the field's current text on expiry; a "Hold" / pause key for the host; in solo mode default to no answer clock.

**[P1] OS `prefers-reduced-motion` is ignored; Podium animations ignore the in-app switch too**

- Where: `game-store.ts:180` (`reducedMotion: false` hard default, no `matchMedia`), `Podium.tsx` (`score-up` scale 1.22, `score-down` shake, `podium-pulse` infinite blink, filter transitions — none gated).
- What: With `reducedMotion: "reduce"` emulated: `mq: true, store: false`, 9 running animations (`board-drop`, `tile-in`, `round-card-zoom`, clue zoom…). Daily Double splash scales 2.4×→1 and the round card zooms. Brief commits to "reduced motion support".
- WCAG: 2.3.3 Animation from Interactions (AAA; product requirement), 2.2.2 for the infinite pulse.
- Fix: Initialise `reducedMotion` from `matchMedia('(prefers-reduced-motion: reduce)')` and subscribe to changes (user switch overrides); pass it to Podium; add a global `@media (prefers-reduced-motion: reduce)` safety net in the theme `CssBaseline`.

**[P1] Buzzer/Reveal/Next keys are 22px tall and start below the fold on phones and at 200% zoom**

- Where: `clue/bench-style.ts:21-25` (`height: 22`), podium layout.
- What: Buzzer measured 112×22 at 320px, 150×22 at 640px; stacked 3px from Reveal. At 320×568 buzzer `top=626` (> viewport 568); at 640×400 (=1280×800 @200%) `top=484` (> 400). The primary control of the game is off-screen when a clue opens and must be scrolled to.
- WCAG: 2.5.8 Target Size Minimum (AA — 24px, spacing exception not met), 1.4.10 Reflow (functionality requires scrolling in 2 dimensions of attention), 2.4.11 (focus/target obscured).
- Fix: Min 44px buzzer (48 on touch); on narrow/short viewports make the buzzer a sticky bottom bar (or the whole clue panel tappable to buzz), and scroll/keep it in view when the clue opens.

**[P1] Board text does not grow with browser zoom (sized from viewport width)**

- Where: `board/BoardFrame.tsx` (`categoryFontSize`, `valueFontSize`), `jeopardy-style.ts` clue scale.
- What: Category font 18px at 1280 wide vs 9.4px at 640 wide (which _is_ 1280 @ 200% zoom) → effective 18.8 device px: zooming to 200% barely enlarges categories; values 46px → 24.8px (49.6 device px). Clue text is 18px at 320 and 640. Root-font 200% (Chrome text-size setting) changes nothing: tile 46px, podium name 12px (px-based type throughout).
- WCAG: 1.4.4 Resize Text (AA).
- Fix: Floor category/clue type at rem-based minimums (e.g. `max(1rem, …cqw)`), let the board grow taller/scroll at narrow widths rather than shrinking type; use rem instead of px for podium/HUD text.

**[P1] Contrast failures: Incorrect key, results chip, selected tabs, faint captions**

- Where/values (axe, verified):
  - Judge "Incorrect" key: #fff on #FF4E5B **3.23:1** at 12px (`JudgeBench.tsx`, `jeopardy-style.ts:24`).
  - Results stat chip (`ResultsView.tsx:186`): #1A1200 on #141A44 **1.11:1** — the score chip text is essentially invisible; rank "1" also near-invisible (see `27-results.png`).
  - Selected tab in Game picker & Builder: #4B5BFF on #0B0F2A **3.79:1** (`ui.blue`).
  - `ui.inkFaint` rgba(255,255,255,.40) on #0B0F2A **3.79:1** — results captions, display join panel text, disabled "LOCKED" buzzer label.
- WCAG: 1.4.3 Contrast (AA).
- Fix: Darken error red for white text (e.g. #D7263D ≥4.5) or use dark text; fix chip colour (it's gold-on-dark text on a dark fill — use gold fill or light text); lighten `ui.blue` for text (~#8A96FF); raise `inkFaint` to ≥0.62 alpha where it carries information.

**[P1] Chat: unlabelled Send button, placeholder-only input, messages not a log**

- Where: `Chat.tsx:98-113`.
- What: axe **critical** `button-name` on the Send IconButton; input has no label (placeholder "Message" only); new messages (including system game-log lines) aren't announced (no `role="log"`). Transcript pane (`TranscriptPane.tsx`) is also a plain region: not `role=log`, focus not moved in, and Esc doesn't close it despite the Shortcuts list saying "Esc — Close overlays".
- WCAG: 4.1.2, 3.3.2, 4.1.3.
- Fix: `aria-label="Send message"`, visually-hidden label for the field, `role="log" aria-live="polite"` on the message list; Esc + focus handling for the transcript.

## P2

**[P2] Dialogs with no accessible name**

- Shortcuts overlay (`ShortcutsOverlay.tsx`, axe serious `aria-dialog-name`), Onboarding, Clue overlay (`aria-label="Clue"` is generic, no category/value), Game picker/Builder/Replay dialogs have no `aria-labelledby`. Settings/Players popovers are unlabeled `div`s (focus lands on unnamed paper).
- WCAG 4.1.2. Fix: `aria-labelledby` pointing to each overline/title; name the clue dialog "Math, $200".

**[P2] Verdict and status conveyed by colour alone**

- Where: `Podium.tsx` buzz light (green/red/white, `aria-hidden`), score red-when-negative, `JudgeBench.tsx` AI confidence % coloured green/red with no "likely correct" text, chat system messages distinguished only by a coloured dot (`Chat.tsx` 70-80), Results "✓ / ✗" glyph labels.
- WCAG 1.4.1 Use of Color, 1.1.1. Fix: text badges ("CORRECT"/"WRONG", "AI: likely correct 92%"), sr-only "correct"/"incorrect" labels instead of ✓/✗.

**[P2] Timer is not perceivable non-visually**

- Where: `BuzzLights.tsx` — `role=progressbar` exposes `valuenow` 0–5 lamps with no `aria-valuetext`; seconds readout `aria-live="off"`; phase label ("Reading…", "Ring in", "Sam rang in") is not live. Results page `LinearProgress` has no name (axe serious `aria-progressbar-name`).
- WCAG 1.3.1, 4.1.2, 4.1.3. Fix: `aria-valuetext="7 seconds left to answer"`; announce phase changes and 5s warning via the announcer.

**[P2] Out-of-range wager silently clamped, no error message**

- Where: `ClueControls.tsx:handleSubmitWager`; wager input min/max only.
- What: Typed 99999 on a $5–$1000 Daily Double + Enter → accepted with no feedback (no `aria-invalid`, no alert) and the clue proceeds.
- WCAG 3.3.1 Error Identification, 3.3.3. Fix: validate before sending, show "Max $1000" helper text with `aria-invalid` + `role=alert`, or confirm the clamped value.

**[P2] Single-character shortcuts can't be turned off/remapped**

- Where: `ClueControls.tsx` (R, Y, N, S), `Room.tsx` (`?`).
- What: Active whenever focus isn't in a text field; speech-control users saying words will trigger reveal/judge/skip. No setting to disable.
- WCAG 2.1.4 Character Key Shortcuts (A). Fix: require modifier or add "Keyboard shortcuts" toggle in Settings; scope to when focus is in the game surface.

**[P2] Repeated, context-free labels in the Custom Game Builder**

- Where: `builder/CategoryCard.tsx` (every row labelled "$", "Clue", "Answer", "DD"), `CustomGameBuilder.tsx:62-71` (category name fields have placeholder only, no label). Import JSON is a `<label role="button">` (axe `aria-allowed-role`).
- WCAG 1.3.1, 2.4.6, 3.3.2. Fix: labels like "Category 1, $200 clue", "…answer", "Daily Double"; real `label` for category name fields; use a `Button component="label"` or a hidden input + button.

**[P2] No landmarks or H1 on any screen; results heading skips levels**

- Where: every screen (axe `landmark-one-main`, `page-has-heading-one`, `region`); Results has h2 → h5; join card h3 → h6.
- WCAG 1.3.1, 2.4.1 Bypass Blocks. Fix: `<header>` for toolbar, `<main>` around GameSurface/Landing, visually-hidden `<h1>` ("Jeopardy — Math vs Colors board"), `<h2>` for board/players; fix heading order.

**[P2] Round intro / Daily Double splash live regions are mounted with their content**

- Where: `RoundIntro.tsx` and `DailyDoubleSplash.tsx` render `role=status` only while visible; screen readers generally don't announce a live region inserted already populated; the splash also uses `aria-label` on a status (not read as content). Subtitles bubble (`AvatarHostController.tsx:88-92`) has the same pattern.
- WCAG 4.1.3. Fix: route these through the persistent announcer from the P0 item.

**[P2] Toolbar & room-code controls below 44px on touch**

- Measured at 320px: toolbar keys 32×32, reveal-code 26×26, room-code chip 71×26. Passes 2.5.8 (24px) but under the 44px touch guideline in the product's "phone buzzing" goal (2.5.5 AAA). Fix: 44px hit area via padding/`::after` on touch (`@media (pointer: coarse)`).

**[P2] Audio-only cues**

- Board `select`, buzz, time-up, Daily Double and Final "think" music are audio SFX (`AvatarHostController.tsx:64-71`, `ClueStage.tsx:187,202-216`). Most have visual counterparts (lamps, splash), but `timeout` (buzz-window-closed / answer-timed-out, `AvatarHostController.tsx:246-262`) has only the lamps going dark — no "Time's up" text anywhere in `src` — and `correct`/`incorrect` sounds pair only with a colour change (light + score colour), no word. WCAG 1.2/1.3.3-ish. Fix: show a brief "Time's up" status text (and announce it).
